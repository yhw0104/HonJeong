# 📋 요구사항명세서 (SRS) — 혼정 (혼밥을 정상화하다)

> 본 문서는 [`01-기획서.md`](./01-기획서.md)의 내용을 개발 가능한 단위의 요구사항으로 분해한 명세서다.
> 기능 요구사항(FR), 비기능 요구사항(NFR), 데이터 개념 모델, 용어/행위자 정의로 구성된다.

| 항목 | 내용 |
| --- | --- |
| 문서 버전 | v1.0 (1단계 기획) |
| 대상 단계 | 전체 로드맵(1~4단계). 단, **1단계(MVP)** 가 우선 개발 범위 |

---

## 1. 행위자(Actor) 정의

| 행위자 | 설명 |
| --- | --- |
| 비회원(Guest) | 가입/로그인 전 사용자. 일부 조회만 가능 |
| 회원(User) | 가입·로그인한 사용자. 체크인·같이먹기·기록 등 핵심 기능 사용 |
| 시스템(System) | 체크인 집계, 통계 산출, 미션/뱃지 부여 등 자동 처리 주체 |
| 관리자(Admin) | (추후) 식당 데이터·신고·운영 관리 |

---

## 2. 용어 정의

| 용어 | 정의 |
| --- | --- |
| 혼밥 체크인 | 사용자가 특정 장소에서 "지금 혼밥 중" 상태를 등록하는 행위 |
| 혼밥러 | 현재 혼밥 체크인 상태인 사용자 |
| 반응(Reaction) *(보류)* | 대화 없이 가벼운 연결감을 주는 행동 ("나도 여기 있음", "같이 먹는 중"). **현재 보류 — 추후 도입** |
| 사회적 증거 | "오늘 N명 혼밥" 등 다수의 동일 행동을 보여주어 심리적 부담을 낮추는 장치 |
| 혼밥 인증 | 혼밥 완료 후 남기는 "혼밥 기준"의 간단 후기/기록 |

---

## 3. 기능 요구사항 (Functional Requirements)

> 우선순위: **P1 = 1단계(MVP)**, P2 = 2단계, P3 = 3단계, P4 = 4단계(선택)

### 3.0 전제 기능 — 계정
| ID | 기능명 | 설명 | 행위자 | 우선순위 |
| --- | --- | --- | --- | --- |
| FR-001 | 회원가입 | **소셜 로그인(OAuth: 카카오/애플) + 휴대폰 번호 인증(SMS)** 으로 가입. 이메일/비밀번호 미사용 | Guest | P1 |
| FR-002 | 로그인/로그아웃 | JWT(Access/Refresh) 발급·검증 | User | P1 |
| FR-003 | 내 프로필 조회/수정 | 닉네임 등 기본 정보 관리 | User | P1 |

### 3.1 MVP (1단계) — 핵심 경험
| ID | 기능명 | 설명 | 행위자 | 우선순위 |
| --- | --- | --- | --- | --- |
| FR-101 | 혼밥 체크인 | **특정 식당(placeId)을 반드시 선택**한 뒤 "지금 혼밥 중" 상태를 등록. **메인 화면의 '혼밥중' 토글이 진입점**으로, 토글 ON=체크인 시작 / OFF=종료(FR-102)에 대응하며 토글은 **내 현재 혼밥 상태(active 여부)를 표시**한다. GPS는 식당 자동 판별이 아니라 주변 후보를 좁히는 보조 수단으로만 사용. 서비스의 데이터 시작점 | User | P1 |
| FR-102 | 체크인 종료 | 혼밥 종료 처리(토글 OFF로 수동 종료 / 미종료 시 자동 만료) | User, System | P1 |
| FR-103 | 혼밥 유저 수 표시 | 메인에 "오늘 혼밥 N명", "현재 혼밥 중 N명" 집계 표시 (사회적 증거) | User, System | P1 |
| FR-104 | 지도 기반 혼밥러 표시 | 지도에서 식당별 현재 혼밥러 수를 핀/마커로 표시 | User | P1 |
| FR-105 | 식당 검색·선택·상세 | 체크인의 **필수 선행 단계**. GPS 기준 주변 식당 후보를 거리순 자동 노출 + 가게명·지역 검색 병행. 식당 기본 정보(placeId·명칭·주소·좌표·카테고리)는 **공공데이터(전국일반음식점표준데이터) 일괄 적재 마스터(우리 DB)** 에서 가져와 체크인 대상 식당을 확정(카카오 로컬 데이터는 약관상 저장불가 → 지도 렌더링 SDK 전용). 식당 선택 시 **식당 상세 화면**을 노출하여 ① 식당 기본 정보 ② 현재 혼밥러 목록(FR-107) ③ "여기서 혼밥" 체크인 버튼(FR-101) ④ 같이먹기(FR-108) 진입점을 한 화면에 모은다 *(반응 FR-106은 보류)* | User | P1 |
| FR-106 | 초간단 반응 *(보류)* | 대화 없이 "나도 여기 있음", "같이 먹는 중" 반응 전송 — **추후 도입(보류)** | User | ~~P1~~ 보류 |
| FR-107 | 같은 식당 혼밥러 목록 조회 | 선택한 식당에 **현재 체크인(active) 중인 혼밥러 목록**을 조회. 같이먹기(FR-108)의 전제 기능 | User | P1 |
| FR-108 | 같이먹기 신청/수락 | 같은 식당에 현재 체크인 중인 혼밥러에게 **같이먹기 인사/신청**을 보내고, 상대가 **수락하면 연결**. **opt-in**(수신 거부 가능)·**차단/신고** 안전장치 적용, 신청 수신 시 **알림**(NFR-08) 제공. 의존: FR-107 | User | P1 |

## 4. 비기능 요구사항 (Non-Functional Requirements)

| ID | 분류 | 요구사항 |
| --- | --- | --- |
| NFR-01 | 인증/인가 | JWT 기반 인증. Access/Refresh 토큰 분리. 인증 필요 API는 토큰 검증 |
| NFR-02 | 보안 | 인증은 OAuth 토큰 서버 검증 + 휴대폰 SMS 인증(공급자 access/refresh 토큰 미저장). API 키·시크릿은 환경변수로 분리(코드/저장소 노출 금지) |
| NFR-03 | 개인정보/프라이버시 | 위치정보는 **목적 최소 수집**. 정확한 좌표 노출 대신 식당/구역 단위로 표시. 체크인은 비식별·집계 우선. 혼밥러 목록은 **정확 좌표·실명 비노출**(닉네임/체크인 경과시간 수준만). 같이먹기는 **opt-in**, **차단/신고** 제공 |
| NFR-04 | 성능 | 실시간 체크인 집계("현재 N명")가 빠르게 반영되어야 함. 지도 마커 조회 응답 지연 최소화 |
| NFR-05 | 확장성 | 단계별 기능 추가(레벨/미션/추천)를 고려한 계층형 아키텍처(Controller-Service-Repository) |
| NFR-06 | 플랫폼 | iOS / Android 양대 플랫폼 지원 (React Native) |
| NFR-07 | 가용성/데이터 정합 | 체크인 종료 누락 시 자동 만료 처리로 "현재 혼밥 중" 수치 정합성 유지 |
| NFR-08 | 알림 | 같이먹기 신청 수신 등 사용자 대상 알림 제공. 방식은 푸시/폴링 중 택1(설계 단계 확정) |

## 5. 데이터 개념 모델 초안

> 정규화·연관관계·인덱스는 **2단계(설계)에서 ERD로 확정**. 아래는 개념 수준.

| 엔티티 | 핵심 속성(초안) | 비고 |
| --- | --- | --- |
| User | id, phone(1차 식별자·인증), email(OAuth 선택), nickname, profileImageUrl, region, diningStyle, allowMealRequest(같이먹기 수신 허용, 기본 true), createdAt | 회원 (소셜+휴대폰 인증) |
| Place | id, externalId(지도 place id), name, address, lat, lng, category | 외부 API 데이터 캐시 |
| CheckIn | id, userId, placeId, startedAt, endedAt, status(active/ended) | 혼밥 체크인 (핵심 데이터) |
| ~~Reaction~~ *(보류)* | id, fromUserId, checkInId, type("here"/"eating_together"), createdAt | 초간단 반응 — **추후 도입(보류)** |
| MealRequest | id, fromUserId, toCheckInId(또는 toUserId), placeId, status(pending/accepted/declined), createdAt | 같이먹기 신청 (1단계) |
| Review (=혼밥일기) | id, userId, checkInId, placeId, visitedAt, mood, content, tasteRating, soloFriendlyRating, createdAt | 리뷰 겸 혼밥일기(통합) — 친화태그(review_tags)·사진(review_photos) (2단계) |
| Badge / Level | id, userId, type, achievedAt | 레벨·뱃지 (2단계) |
| Mission | id, title, condition, rewardBadgeId / UserMission(진행상태) | 미션 (3단계) |

핵심 관계(요약): `User 1—N CheckIn`, `Place 1—N CheckIn`, `User 1—N Review/MealRequest`. `MealRequest`는 대상 혼밥러의 (active) `CheckIn`을 참조하며, `CheckIn`이 사회적 증거 통계(FR-103/104)의 집계 원천이다. *(Reaction은 보류.)*
